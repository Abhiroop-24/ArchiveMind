ArchiveMind · Hybrid Database Architecture Abstract & Contents

ABSTRACT

Historical manuscript libraries, university special collections, and national archives house millions of digitized folios. While photographic scanning preserves physical artifacts against organic decay, researchers face fundamental retrieval trade-offs: conventional relational databases (RDBMS) support precise metadata querying and B-Tree indexing but fail on noisy OCR transcripts or visual handwriting similarity; conversely, standalone vector databases excel at neural stroke-pattern retrieval but lack referential integrity, foreign key cascades, multi-table joins, transactions, role-based access control, and verifiable audit trails.

ArchiveMind addresses this dual limitation by presenting a hybrid SQL-Vector semantic search architecture tailored for digitized historical document repositories. The system couples a 3NF normalized relational schema in PostgreSQL/SQLite with dense 128-dimensional handwriting feature embeddings extracted from stroke contour moments. The platform incorporates:

  • Hybrid Convex Retrieval: Dynamically fuses SQL Full-Text Search (FTS5 BM25) with cosine vector distance scoring ($Score = lpha \cdot FTS + (1-lpha) \cdot Cosine$).
  • Automated Triggers: Fires database-level triggers on document viewing and scholarly citation creation, maintaining an immutable chain of custody in DOCUMENT_VIEW.
  • Role-Based Access Control (RBAC): Enforces strict privilege boundaries between Head Archivists (with DDL/DML mutation rights) and Academic Researchers (read-only inspection and citation generation).

CHAPTER 1: INTRODUCTION

1.1 Background & Context

Cultural heritage preservation organizations, including university manuscript departments, national archival repositories, and specialized scholarly foundations, hold millions of irreplaceable historical documents. Prominent historical manuscripts include draft scientific treatises by Sir Isaac Newton (e.g., draft folios of Philosophiae Naturalis Principia Mathematica and Opticks), anatomical codices and mechanical designs by Leonardo da Vinci, mathematical folios from Srinivasa Ramanujan's Lost Notebook, wartime cryptanalytic memos by Alan Turing from Bletchley Park, and Victorian computational algorithms by Ada Lovelace and Charles Babbage.

In recent decades, digital preservation initiatives have transitioned physical paper and parchment into high-resolution digital image formats (TIFF, JPEG2000). However, simple photographic digitization does not equate to effective preservation or deep searchability. Researchers require advanced tools capable of executing precise keyword lookups across historical Optical Character Recognition (OCR) transcripts, alongside forensic handwriting visual style similarity across unsigned documents.

1.2 Motivation

Relational Database Management Systems (RDBMS) like PostgreSQL and SQLite excel at managing structured institutional metadata. They provide ACID transaction guarantees, referential integrity via foreign key constraints, fine-grained access control, and fast B-Tree/GIN indexing for exact string queries. However, pure relational databases fail when searching noisy historical OCR texts with archaic orthography or when attributing anonymous folios based on handwriting style.

Conversely, modern Vector Databases store high-dimensional neural embeddings and execute fast approximate nearest-neighbor (ANN) searches. However, standalone vector databases lack relational schemas, foreign key cascades, atomic multi-table transactions, analytical aggregations (GROUP BY, COUNT), and immutable audit logs.

Core Research Problem

How can relational rigor (3NF schema, referential integrity, ACID transactions, stored procedures, triggers, and RBAC) be unified with high-dimensional vector similarity search into a single coherent database engine?

1.3 System Objectives

  • Normalized Relational Architecture: Establish a 3NF relational schema capturing institutional repositories, collections, documents, historical authors, handwriting samples, citations, and audit view logs.
  • Convex Hybrid Fusion: Provide dynamic ranking blending SQL Full-Text Search (BM25 token relevance) with 128-dimensional handwriting feature vector cosine similarity.
  • Automated Integrity & Audit Triggers: Enforce cryptographic SHA-256 checksum integrity and automatically log chain-of-custody audit records whenever manuscripts are inspected or cited.
  • Role-Based Access Control: Enforce backend security boundaries isolating administrative mutations from researcher queries.

CHAPTER 2: PROBLEM DEFINITION

2.1 Limitations of Existing Systems

Existing archival management systems typically adopt one of two bifurcated architectures, both of which introduce severe bottlenecks:

  1. Pure Relational Keyword Systems: Rely solely on SQL LIKE operators or basic inverted text indexes. Historical manuscripts exhibit archaic vocabulary, ink bleeding, and transcription gaps. A query for "refraction" fails to match historical Latin transcripts reading "refrangibilitate radiorum", yielding high false-negative rates.
  2. Pure Vector Search Engines: Store documents as unconstrained embedding vectors. These systems cannot answer relational institutional queries such as "Count manuscripts authored by Isaac Newton grouped by physical condition in the Cambridge Digital Archives", nor can they enforce foreign key constraints when manuscripts are transferred between collections.

2.2 Proposed Solution: ArchiveMind Engine

ArchiveMind implements a hybrid engine uniting relational tables with dense vector representations:

ScoreHybrid(d, q) = α · ScoreFTS(d, q) + (1 − α) · SimCosine(v⃗d, v⃗q)

where α ∈ [0, 1] is an adjustable tuning parameter allowing scholars to shift weighting between exact SQL keyword matching (α = 1.0) and handwriting stroke forensic alignment (α = 0.0).

CHAPTER 4: 3NF NORMALIZATION & RELATIONAL SCHEMA

4.1 Normalization Proofs (1NF → 2NF → 3NF)

To prevent insertion, update, and deletion anomalies, all relations in ArchiveMind are rigorously normalized to Third Normal Form (3NF):

First Normal Form (1NF) Compliance

All attributes are atomic and indivisible. Multi-valued attributes like multiple authors are decomposed into the associative entity DOCUMENT_AUTHOR rather than stored as comma-delimited strings within the DOCUMENT relation.

Second Normal Form (2NF) Compliance

The relation is in 1NF and contains no partial functional dependencies. In relations with composite keys like DOCUMENT_AUTHOR(document_id, person_id), non-key attributes (attribution_type, confidence_score) depend on the complete composite primary key, not a proper subset.

Third Normal Form (3NF) Compliance

The relation is in 2NF and contains no transitive functional dependencies ($X ightarrow Y$ and $Y ightarrow Z$ where $Z$ is non-prime). For instance, archive details (location, institution) are not stored inside COLLECTION; instead, collection_id → archive_id and archive_id → (name, location, institution) are factored into a dedicated ARCHIVE relation.

4.2 Formal Relational Schema Specification

  • ROLE (role_id, role_name)

7.1 Simple Query with GROUP BY & Aggregate Functions

Objective: Aggregates manuscript holdings across archival eras and physical conditions, computing total counts and average OCR text length.

Relational Algebra Expression

γc.era, d.physical_condition, COUNT(d.document_id)→total_docs, AVG(LENGTH(d.ocr_text_cache))→avg_len (COLLECTION ⋈c.collection_id = d.collection_id DOCUMENT) 

SELECT 
    c.era,
    d.physical_condition,
    COUNT(d.document_id) AS total_manuscripts,
    ROUND(AVG(LENGTH(d.ocr_text_cache)), 2) AS avg_ocr_length,
    MIN(d.date_written) AS oldest_record,
    MAX(d.date_written) AS newest_record
FROM document d
JOIN collection c ON d.collection_id = c.collection_id
GROUP BY c.era, d.physical_condition
ORDER BY c.era ASC, total_manuscripts DESC;

7.4 Correlated Subquery

Objective: Identifies manuscripts whose OCR transcript length strictly exceeds the average OCR text length of documents within their own specific collection.

Relational Algebra Formulation

σLENGTH(d1.ocr_text_cache) > AVG_COL_LEN (DOCUMENT d1 ⋈ COLLECTION c) 

SELECT 
    d1.document_id,
    d1.title,
    c.name AS collection_name,
    LENGTH(d1.ocr_text_cache) AS manuscript_chars
FROM document d1
JOIN collection c ON d1.collection_id = c.collection_id
WHERE LENGTH(d1.ocr_text_cache) > (
    SELECT AVG(LENGTH(d2.ocr_text_cache))
    FROM document d2
    WHERE d2.collection_id = d1.collection_id
)
ORDER BY manuscript_chars DESC;

CHAPTER 8: STORED PROCEDURES & TRIGGERS

8.1 Stored Procedures: Citation Engine

The stored procedure formats archival citations in Chicago-Archival, MLA, or APA style, executing within an isolated transaction: 

CREATE OR REPLACE PROCEDURE sp_generate_archival_citation(
    IN p_document_id INT,
    IN p_user_id INT,
    IN p_style VARCHAR(30) DEFAULT 'Chicago-Archival'
)
LANGUAGE plpgsql AS $$
DECLARE
    v_title VARCHAR(255);
    v_date VARCHAR(50);
    v_archive_name VARCHAR(150);
    v_col_name VARCHAR(150);
    v_author_name VARCHAR(150);
    v_citation_text TEXT;
BEGIN
    SELECT d.title, d.date_written, c.name, a.name, COALESCE(p.full_name, 'Unknown Author')
    INTO v_title, v_date, v_col_name, v_archive_name, v_author_name
    FROM document d
    JOIN collection c ON d.collection_id = c.collection_id
    JOIN archive a ON c.archive_id = a.archive_id
    LEFT JOIN document_author da ON d.document_id = da.document_id
    LEFT JOIN person p ON da.person_id = p.person_id
    WHERE d.document_id = p_document_id LIMIT 1;

    IF p_style = 'MLA' THEN
        v_citation_text := v_author_name || '. "' || v_title || '." ' || v_date || '. ' || v_col_name || ', ' || v_archive_name || '.';
    ELSE
        v_citation_text := v_author_name || ', ' || v_title || ' (' || v_date || '), ' || v_col_name || ', ' || v_archive_name || '.';
    END IF;

    INSERT INTO citation (document_id, user_id, citation_text, citation_style, generated_at)
    VALUES (p_document_id, p_user_id, v_citation_text, p_style, CURRENT_TIMESTAMP);
    COMMIT;
END;
$$;

8.2 Database Triggers

Trigger 1: Checksum Integrity Validation

Prevents accidental or malicious modification of document records with truncated or empty SHA-256 integrity hashes. 

CREATE TRIGGER trg_validate_doc_checksum
BEFORE UPDATE OF checksum_value ON document
BEGIN
    SELECT CASE 
        WHEN LENGTH(NEW.checksum_value) < 16 THEN
            RAISE(ABORT, 'Integrity Error: Cryptographic checksum truncated.')
    END;
END;
Trigger 2: Citation Generation Audit Trigger

Automatically inserts an immutable chain-of-custody audit entry into DOCUMENT_VIEW whenever a citation is created, capturing the researcher's user ID and timestamp. 

CREATE TRIGGER trg_audit_citation_generation
AFTER INSERT ON citation
BEGIN
    INSERT INTO document_view (document_id, user_id, ip_address, viewed_at)
    VALUES (
        NEW.document_id,
        COALESCE(NEW.user_id, 3),
        '127.0.0.1 [TRIGGER:CITATION_' || UPPER(NEW.citation_style) || ']',
        CURRENT_TIMESTAMP
    );
END;

9.1 Design System & Aesthetic Principles

The ArchiveMind front end rejects colorful, generic templates in favor of a pure monochrome brutalist aesthetic inspired by Nothing OS and Omarchy Vantablack:

  • Typographic Hierarchy: Clean grotesque sans-serif (Inter) paired with monospaced accents (Geist Mono) for cryptographic hashes and SQL code blocks.
  • Interactive Provenance Graph: HTML5 Canvas rendering topological nodes tracing Author → Document → Collection → Archive → Audit Node.

CHAPTER 10: CONCLUSION & FUTURE SCOPE

ArchiveMind successfully demonstrates the convergence of classical relational database management systems with high-dimensional vector similarity forensics. By housing full-text search virtual tables, relational provenance chains, cryptographic integrity triggers, and dense 128-dimensional handwriting feature embeddings within a unified architecture, the system offers academic researchers a robust tool for historical manuscript exploration.

Future Scope: Expanding the vector indexing engine to utilize approximate nearest-neighbor HNSW (Hierarchical Navigable Small World) graphs via PostgreSQL pgvector, integrating multi-page codex stitching, and deploying distributed write replicas.
